# 2D game art with open-source tools

Sprites, tiles, textures, UI and fonts for 2D games, made with open-source tools and exported
by a script you can rerun. Every tool, license and command below was checked against its
repository or official documentation on 2026-09-23; shell commands were run on ImageMagick 6.9
and Inkscape 1.2. The ImageMagick lines use version 7's `magick` command; on ImageMagick 6, write
`montage` for `magick montage` and `convert` for a bare `magick`. 3D art: [blender.md](blender.md).
Engines: [../engines/](../engines/).
Starter projects: [../scaffolds/README.md](../scaffolds/README.md#shortlist-by-engine).

## What the tool licenses mean for your art

- **GIMP's FAQ:** "Can I use GIMP commercially? Yes, you can. GIMP is free software, it doesn't
  put restrictions on the kind of work you produce with it." GIMP's LICENSE file adds that
  bundled brushes, patterns and other data "should be under a CC0 license", while saying it
  cannot guarantee that for older data.
- **Krita's FAQ:** "What you create with Krita is your sole property. You own your work and can
  license your art however you want. Krita's GPL license applies to Krita's source code."
- **Inkscape's FAQ** covers using the program ("for any purpose, commercial or non-commercial")
  but does not address the drawings you make. The general rule is in section 2 of the GPL-3.0
  itself: "The output from running a covered work is covered by this License only if the
  output, given its content, constitutes a covered work." The GNU GPL FAQ's exception is
  content the program copies into your output, such as bundled clip art or templates; check the
  license of any stock asset you keep in a final image.
- **Tool code is not your code.** The source of GIMP, Krita, Inkscape, LibreSprite and the Tiled
  editor is GPL: `study only` in this repository's terms. Pixelorama, Piskel, Material Maker,
  LDtk and free-tex-packer are permissive (`copy`), with attribution in your
  [THIRD_PARTY.md](../templates/THIRD_PARTY.md).
- **Aseprite** is readable on GitHub but its EULA allows you to "compile and modify the source
  code ... for your own personal purpose or to propose a contribution" and says "You may not
  distribute copies". Some of its libraries (laf, clip, undo, ui) are MIT. LibreSprite is a fork
  of the last commit before Aseprite left the GPL on 2016-08-26, developed independently since.

## GIMP: textures, photo sources, batch work

GIMP 3 keeps most GEGL filters editable after you apply them (non-destructive filters) and
runs plug-ins in Python 3, Script-Fu or C.

- **Seamless textures:** Filters > Map > Tile Seamless, then test by tiling the result 3x3.
- **Palette lock:** Image > Mode > Indexed with "Use custom palette" maps an image onto your
  project palette, with dithering optional.
- **Layers to files:** [Batcher](https://github.com/kamilburda/batcher) (BSD-3-Clause, GIMP 3)
  exports each layer as its own image and batch-converts files. Its predecessor, Export Layers,
  is unmaintained and GIMP 2 only. Keep one frame per layer, export, then build the sheet with
  ImageMagick or a packer (below). Install release 1.2.10 from its GitHub releases page; like
  every plug-in, it runs Python inside GIMP with your permissions.
- **Headless batch:** `gimp-console` runs without a window. The default batch interpreter is
  Script-Fu; GIMP 3 also ships `python-fu-eval`, which reads code from standard input when the
  command is `-`, with `Gimp`, `Gegl` and `Gio` already imported:

  ```sh
  gimp-console --batch-interpreter python-fu-eval -b - --quit < tools/gimp_job.py
  ```

- **GEGL**, GIMP's image engine (LGPL-3.0 library), has a `gegl` command-line tool that chains
  the same operations GIMP uses.
- **PNG export:** "Save color values from transparent pixels" is off by default. Turn it on if
  you painted edge colors into transparent pixels to prevent dark fringes (see Pitfalls).

## Krita: painted art and animation

- **Painting:** many brush engines, and View > Wrap Around Mode, which shows the canvas tiled
  so you can paint seamless textures across the edges.
- **Animation:** the Animation Timeline and Onion Skin dockers for frame-by-frame work. Render
  Animation writes an image sequence (and GIF or video; Krita has bundled part of FFmpeg since
  5.2). Feed the frames to the sheet step below.
- **Batch Exporter** ships with Krita as a Python plugin: tag a layer's name, such as
  `Torso e=png s=50,100 m=2`, and it exports that layer as PNG at 50% and 100% with a 2 px
  margin, turning groups into folders. It exports with an sRGB profile by default. Enable it in
  Settings > Configure Krita > Python Plugin Manager, then restart Krita.

## Inkscape: vector art, UI and multi-scale exports

Draw UI, icons and flat-style art as vectors once, then export each resolution you ship.
Inkscape uses 96 DPI internally, so `--export-dpi=96` exports a 32 px wide document at 32 px,
and 192 is exactly 2x:

```sh
for s in 1 2 4; do
  inkscape art-src/ui/buttons.svg --export-type=png --export-dpi=$((96 * s)) \
    --export-filename=assets/art/ui/buttons@${s}x.png
done
# one object by its id: add --export-id=btn_play --export-id-only
```

Inkscape and GIMP share the `.gpl` palette format, so one palette file serves both.

## Pixel art

- **Pixelorama** (MIT, built with Godot): layer and frame timeline, onion skinning, tilemap
  layers (rectangular, isometric, hexagonal), indexed mode, pixel-art rotation and scaling
  (cleanEdge, OmniScale, rotxel), and export to PNG, sprite sheets, GIF and video. Its
  [command-line interface](https://orama-interactive.github.io/Pixelorama-Docs) exports
  headless (`--headless --quit`) with `--spritesheet`, `--output`, `--scale`, `--json` and
  `--split-layers`, so it fits in an export script.
- **LibreSprite** (GPL-2.0): layers and frames, onion skinning, real-time preview, a tiled
  drawing mode for patterns.
- **Piskel** (Apache-2.0): a sprite editor that runs in the browser.
- **Aseprite** is not open source (above). If you already own it,
  [godot-aseprite-wizard](https://github.com/viniciusgerevini/godot-aseprite-wizard) (MIT)
  imports its files into Godot 4 as SpriteFrames and AnimationPlayer tracks. It runs the Aseprite
  command you configure (through `OS.execute`) and reads `.aseprite` files inside the project, so
  with it those files are engine files, not `art-src/` sources. Pin release v9.8.0-4.

Pixel art in the engine: nearest-neighbor filtering, integer scaling, and no lossy
compression. In Godot 4, filtering is a CanvasItem property with a project-wide default
(`rendering/textures/canvas_textures/default_texture_filter`), and the import docs call the
Lossless compress mode "the recommended setting for pixel art".

## Procedural textures: Material Maker

Material Maker (MIT) builds textures from a node graph and runs on Godot. It exports PNG maps
for every channel plus engine files: a `.tres` material for Godot, a `.mat` for Unity, a
Python setup script for Unreal Engine 5, and images for Blender. Use it for tileable ground,
walls and noise backgrounds, then bake to PNG for 2D. Batch export from the command line:

```sh
material_maker --export-material --target Godot -o assets/art/materials art-src/materials/*.ptex
```

## Sprite sheets and texture atlases

- **A simple grid:** ImageMagick joins zero-padded frames into a sheet with no spacing
  (`-tile 8x` means eight columns):

  ```sh
  magick montage frames/hero_walk_*.png -tile 8x -geometry +0+0 -background none hero_walk.png
  ```

- **free-tex-packer** (MIT) packs sprites with rotation, trimming and multiple sheets, and
  writes JSON, XML, CSS, pixi.js, Godot, Phaser and cocos2d data. The desktop app is in
  maintenance mode ("Only critical bugs will be fixed"). Its engine,
  [free-tex-packer-core](https://github.com/odrick/free-tex-packer-core) (MIT, still updated),
  exposes `padding`, `extrude`, `powerOfTwo`, `allowRotation` and `allowTrim` for build
  scripts.
- **TexturePacker** is proprietary and sold as a per-user license with a free trial.

## Tile maps

- **Tiled:** any tile size, any number of layers, custom properties on maps, layers, tiles and
  objects. Terrain sets (corner, edge, mixed) paint transitions; Automapping applies rule-based
  placement. It exports JSON, Lua and CSV, and has Godot 4, Defold and GameMaker exporters.
  From a script: `tiled --export-map json art-src/levels/level1.tmx assets/levels/level1.json`
  (`tiled --export-formats` lists the names). Importers, both MIT:
  [YATI](https://github.com/Kiamo2/YATI) for Godot 4 (release v2.2.7; we found no process or
  network calls in its GDScript) and
  [SuperTiled2Unity](https://github.com/Seanba/SuperTiled2Unity) for Unity (a Unity package from
  its itch.io page; tag v2.3.0). They read `.tmx` files inside the engine project, so with one of
  them the map and its tilesets are engine files, not `art-src/` sources.
- **LDtk:** levels built on IntGrid layers; auto-layers paint tiles from neighbor rules (for
  example, place this tile where a cell holds a collision value and the cell above does not),
  and LDtk "saves its data in pure JSON format". For Godot 4,
  [godot-ldtk-importer](https://github.com/heygleeson/godot-ldtk-importer) (MIT; release 2.0.1,
  last push 2025-02-02, so confirm it supports your Godot version; we found no process or network
  calls in its GDScript).

## Fonts

Use fonts under the SIL Open Font License (OFL) or another license that allows bundling. The
[OFL FAQ](https://openfontlicense.org/ofl-faq/) says you may sell software that includes OFL
fonts, naming "games and entertainment software" (1.4); you must ship "the copyright statement,
the license notice and the license text" (1.20); graphics you make with the font stay yours
(1.1.1); and a modified or rebuilt font must respect the author's Reserved Font Names (5.9).
The [google/fonts](https://github.com/google/fonts) repository files every family under a
folder named for its license (`ofl`, `apache`, `ufl`, `cc-by-sa`); pixel-style families in
`ofl` include Press Start 2P, Silkscreen, Pixelify Sans and VT323, each with its `OFL.txt`.
Never ship a font copied from your operating system.

## Palettes

Pick one palette per project before drawing. The
[Lospec palette list](https://lospec.com/palette-list) downloads palettes as `.gpl`, `.pal`,
`.hex` and PNG; the list page states no license, so credit the palette's author. `.gpl` opens
in GIMP, Inkscape, Krita and Pixelorama. Enforce the palette on imported or generated art with
`magick input.png -dither None -remap palette.png output.png`.

## Art direction for a small team

- **One style sheet page:** pixels per tile or world unit, camera zoom, the palette file, outline
  rule (none, dark, colored), light direction, shading steps, and animation frame rate.
- **Template files** for each canvas size (tile, character, portrait, icon), committed to the
  repository, so every artist starts at the same scale.
- **Sources and exports apart.** Editable sources (`.xcf`, `.kra`, `.svg`, `.pxo`, `.aseprite`,
  `.ptex`) live in an `art-src/` folder outside the engine project's import path. A script writes
  the engine-ready files into the project's assets folder, and nobody edits those by hand:

  ```text
  art-src/        sources; the engine never imports them
  assets/art/     exports, for a Godot project at the repository root
  Assets/Art/     exports, for Unity, which imports only under Assets/
  ```

  When the Godot project is the repository root, `art-src/` sits inside it: put an empty
  `art-src/.gdignore` there, or Godot imports every source `.svg` and frame `.png`. Unity ignores
  folders outside `Assets/`, so `art-src/` beside `Assets/` needs nothing.
- **Review in the engine at game resolution**, next to existing art, not zoomed in an editor.

## Automate the exports

One script rebuilds every export, so a changed palette or scale is one command, and CI can
run it. This version was run end to end, with ImageMagick 6's `montage` in place of
`magick montage`.

```sh
#!/usr/bin/env bash
# tools/export_art.sh [out]: rebuild every export from art-src/ into the engine's assets folder.
#   Godot: tools/export_art.sh assets/art    Unity: tools/export_art.sh Assets/Art
set -euo pipefail; shopt -s nullglob
src=art-src; out=${1:-assets/art}
tmp=$(mktemp -d); trap 'rm -rf "$tmp"' EXIT   # build outside the project, copy in only on success
mkdir -p "$tmp/ui" "$tmp/sprites"
svgs=("$src"/ui/*.svg)                     # vector UI at 1x, 2x, 4x
for svg in "${svgs[@]}"; do
  name=$(basename "$svg" .svg)
  for s in 1 2 4; do
    inkscape "$svg" --export-type=png --export-dpi=$((96 * s)) \
      --export-filename="$tmp/ui/${name}@${s}x.png" 2>/dev/null
  done
done
anims=("$src"/sprites/*/)                  # one folder of zero-padded frames per animation
for dir in "${anims[@]}"; do
  magick montage "$dir"*.png -tile 8x -geometry +0+0 -background none \
    "$tmp/sprites/$(basename "$dir").png"
done
want=$(( ${#svgs[@]} * 3 + ${#anims[@]} ))  # reconcile: expected count equals written count
have=$(find "$tmp" -name '*.png' | wc -l)
[ "$want" -eq "$have" ] || { echo "expected $want PNGs, found $have; $out unchanged" >&2; exit 1; }
mkdir -p "$out"
cp -R "$tmp"/. "$out"/     # overwrite in place: keeps Godot .import and Unity .meta files
echo "exported $have files to $out"
```

The count check is not decoration: given a corrupt SVG, Inkscape 1.2 exited 0 and wrote
nothing, and only the reconcile line failed the run. The script copies over the old exports
rather than deleting the folder, because Godot's `.import` and Unity's `.meta` files sit next to
each export and hold the IDs your scenes and prefabs reference. When you delete a source, delete
its export inside the engine editor, which removes the matching `.import` or `.meta` file too.

## AI assistance

**MCP servers** let an AI client operate a running art tool. Read the
[safe setup checklist](../ai/graphics.md#safe-setup-checklist) before installing any of them. The
ones this repository found are listed in [../scaffolds/mcps.md](../scaffolds/mcps.md); for 2D, each
read at its source on 2026-09-23:

- [maorcc/gimp-mcp](https://github.com/maorcc/gimp-mcp) (GPL-3.0, GIMP 3.2). **Listens:** a GIMP
  plug-in on `localhost:9877` (plain TCP), and we found no authentication in its source. **Runs:**
  its README documents a message format "for arbitrary exec" of Python, so while it runs any local
  process can run code inside GIMP. **Sends:** we found no telemetry; the MCP server talks to your
  client over stdio. **Install:** no releases, so `git clone`, `git checkout 09bfb2d` (or a later
  commit you have read), `uv sync` (it ships a `uv.lock`), then copy the plug-in into GIMP's
  `plug-ins` folder.
- [nanayax3/krita-mcp](https://github.com/nanayax3/krita-mcp) (MIT). **Listens:** a Krita plugin
  serving HTTP on `localhost:5678`, started whenever Krita opens a window while the plugin is
  enabled. **No authentication and no Origin check:** it parses any POST body as JSON, so a web
  page open in your browser can send it commands, including save and open at any path. Enable it
  only for a session with no browser open and disable it afterwards, or skip it. **Install:** copy
  the plugin into Krita's `pykrita` folder, then `pip install fastmcp httpx`, which its README
  leaves unpinned: pin both. It has one commit (2026-02-26) and 10 open pull requests
  nobody has merged.
- **Not recommended:** [libreearth/gimp-mcp](https://github.com/libreearth/gimp-mcp). Its README's
  install steps clone a different repository and name files that are not in this one, its plug-in
  lets any local process call any GIMP API function on `localhost:9876` without authentication,
  and every commit is from 2025-03-18.

Running a GPL server locally is fine (the GPL-3.0 "affirms your unlimited permission to run the
unmodified Program"); copying its code into your game is `study only`. **These servers and every
art-tool add-on or engine importer named in this guide run code with your permissions.** Krita's
manual says it plainly: "a Python
plugin can do everything that Krita can do, which means for example access to your files."

1. Prefer well-maintained projects with recent commits and real issue activity.
2. Read the plug-in and server code before installing; look for `exec`, `eval`, shell calls,
   network listeners and file writes outside the project.
3. Pin a release or commit, and pin its dependencies; never install from a moving branch, and
   never pipe a downloaded install script into a shell without reading and pinning it first.
4. Least privilege: a separate OS user, container or VM, with only the project's art folders.
5. Never expose an MCP server to the network: keep it on `localhost`, never bind `0.0.0.0`,
   never port-forward it, and stop it when you are done.
6. Commit before an AI session, so every change it makes can be reviewed and reverted.

**AI-generated images.** The U.S. Copyright Office (January 29, 2025) concluded that AI output
"can be protected by copyright only where a human author has determined sufficient expressive
elements", not by "the mere provision of prompts", while AI-assisted work inside a larger human
work stays protectable. So in the U.S. a generated sprite you did not substantially rework may
have no copyright owner, including you. Generators' terms and training data differ; read the
terms of the exact service and model before shipping output, and never prompt for a living
artist's style or a trademarked character. Steam's Content Survey requires disclosing
"Pre-Generated" AI content that ships in a game, and the guardrails on "Live-Generated" content.

**Record provenance in one place,** from the first asset: the game's
[`THIRD_PARTY.md`](../templates/THIRD_PARTY.md#ai-generated-and-ai-assisted-assets), in its "AI-generated and AI-assisted assets"
section. For each file or folder, note the tool and model, the prompt or input, the date, the
terms it came under and what a person changed afterwards.

## Pitfalls

- **Dark or white fringes around sprites.** With straight (non-premultiplied) alpha, filtering
  blends an edge pixel with the hidden color of its transparent neighbor. Fill transparent
  pixels with edge colors (and enable GIMP's "Save color values from transparent pixels"), or
  let the engine do it: Godot's Fix Alpha Border import option, on by default. Premultiplied
  alpha also fixes it, but only with a matching blend mode (in Godot, Premult Alpha on import
  plus a CanvasItemMaterial set to Premultiplied Alpha). Never premultiply twice.
- **Color spaces.** Export color art as 8-bit sRGB. GIMP 3 supports color spaces beyond sRGB,
  so check what an export embeds. Normal maps and masks are data, not color; normal maps also
  come in OpenGL (Y+) and DirectX conventions, and Godot expects Y+ (Normal Map Invert Y
  converts).
- **Texture bleeding.** Neighbors in an atlas or tileset bleed in under linear filtering or
  mipmaps. Add padding and extrude edge pixels (free-tex-packer-core's `padding` and `extrude`),
  or use nearest filtering without mipmaps for pixel art.
- **Power-of-two sizes.** Godot recommends them but does not require them. WebGL 1 restricts
  the rest: a non-power-of-two texture there cannot have mipmaps and must clamp to edge (MDN).
  Check the oldest target you ship to.
- **Frame order.** `walk_10.png` sorts before `walk_2.png`; zero-pad frame numbers.
- **Pixel art scaling.** Scale by whole numbers (`magick in.png -scale 400% out.png` keeps hard
  pixels); a fractional scale makes some pixels wider than others.
- **Lossy compression on pixel art** smears it; use lossless (Godot: Lossless compress mode).
